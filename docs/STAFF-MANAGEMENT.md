# Управление сотрудниками (решение владельца, 2026-10-18)

Всё в кабинете: **Настройки → Сотрудники** (видит только владелец). Владелец — супер-админ, ему доступно всё без ограничений по правам.

## Что может владелец

| Действие | Где | Правило |
|---|---|---|
| Добавить управляющего | «+ Управляющий»: ФИО, телефон, начальный пароль | Новый сотрудник — роль ADMIN со стартовыми правами (жильцы, финансы); права на комнаты и прочее выдаются отдельно |
| Изменить данные | значок карандаша у сотрудника | ФИО и телефон; телефон должен быть свободен |
| Сбросить пароль | значок ключа | Владелец задаёт новый пароль (от 8 символов); все сеансы сотрудника закрываются, вход с нового устройства снова подтверждается в Telegram |
| Отключить / Включить | кнопка | Отключённый не может войти; остаётся в списке и в истории |
| Удалить | значок корзины | Только если сотрудник **ни разу не входил и не работал**. Иначе — отключение (журнал нельзя менять, история должна сохраниться) |
| Сделать владельцем | значок короны, с подтверждением | Сотрудник становится полным супер-админом: управляет комнатами, сотрудниками, правами, подтверждает входы в Telegram. В приложении не отменяется |
| Права сотрудника | «Права сотрудников» | Галочками: комнаты, жильцы, финансы, заявки, обращения, карта/геолокация. Шаблоны ролей. Права владельца изменить нельзя |

## Почему так

- **Журнал действий неизменяем** (защита на уровне базы). Поэтому сотрудника, который уже входил или что-то делал, нельзя удалить — только отключить: иначе в истории остались бы «висячие» записи без автора. Удаление — только для ошибочно созданной, ни разу не использованной записи.
- **«Сделать владельцем»** — сильное право, поэтому требует подтверждения и в кабинете, и на сервере (`confirm`). Понизить владельца обратно через приложение нельзя (защита от случайной потери доступа); при необходимости — отдельная операция на сервере.
- Пароли и сбросы: сервер проверяет длину и права, подделать через кабинет нельзя. Пароль сотрудника владельцу не виден — хранится только его шифрованный отпечаток.

## API (всё под `SUPER_ADMIN`)

- `POST /users` — создать управляющего
- `PATCH /users/:id` — включить/отключить (`active`)
- `POST /users/:id/profile` — изменить ФИО/телефон
- `POST /users/:id/password` — сбросить пароль
- `DELETE /users/:id` — удалить (только без истории)
- `POST /users/:id/owner` — сделать владельцем (`confirm: true`)
- `PUT /permissions/users/:id` — выдать права

Каждое действие пишется в журнал (раздел «История»): `ADMIN_CREATED`, `ADMIN_PROFILE_CHANGED`, `ADMIN_PASSWORD_RESET`, `ADMIN_ACCESS_CHANGED`, `ADMIN_DELETED`, `ADMIN_PROMOTED_TO_OWNER`.
