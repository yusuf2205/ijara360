На NAS уже доступен SSH пользователя Joseph и работает Gitea. Его SSH-порт опубликован как `192.168.1.105:222`; адрес Git по локальной сети — `ssh://git@192.168.1.105:222/joseph/ijara360.git`. Он относится к тому же репозиторию, что web-адрес mygithub.uz. Учётная запись NAS и доступ к Git-репозиторию Gitea проверяются отдельно.

## Публикация

Работа ведётся в одной истории `main`; оба Git remote получают один и тот же commit. Force push, удаление чужих веток и `push --mirror` не используются. Если удалённая история отличается, сначала fetch и сверка; чужие изменения не перезаписываются.

После нового commit:

1. `git push github main` и проверить remote SHA.
2. `git push mygithub main` и проверить remote SHA.
3. Создать `git archive` и `git bundle create ... main` из этого commit.
4. Скопировать архив, bundle и SHA-256 manifest на NAS в каталог с полным commit ID.
5. На NAS проверить SHA-256 и распаковать исходники. Сохранённые версии не удаляются автоматически.

Публикация выполняется командой `powershell -File scripts/Publish-Project.ps1` после настройки доступа. Если локальная ExecutionPolicy запрещает скрипты, однократный запуск требует разрешения пользователя: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Publish-Project.ps1`; постоянная политика Windows не меняется. Скрипт проверяет чистоту отслеживаемого дерева, ветку main и отправляет обеим площадкам точный HEAD. При недоступности одной площадки сохраняет на остальных и завершает работу с ошибкой, чтобы частичная публикация не считалась полной. Параметр `-SkipGitea` предназначен только для явно отмеченной промежуточной публикации до подключения Gitea; это не полная синхронизация.

Передача на UGOS использует `scp -O`: SFTP на этом NAS имеет другое представление корневого каталога, а legacy SCP обращается к тому же абсолютному пути, который проверен через SSH. Транспорт остаётся зашифрованным SSH. Неполные каталоги после ошибки сохраняются для проверки и не выдаются за успешные релизы.

Автоматическая периодическая синхронизация не настроена. Публикация новых коммитов выполняется явным запуском скрипта. GitHub и mygithub.uz не хранят работающий процесс приложения.

## Данные и секреты

В репозитории входят исходники, миграции, документация и шаблоны конфигурации без секретов. Не коммитить `.env`, приватные SSH-ключи, пароли камер, токены, дампы БД, документы жильцов и видео. `.gitignore` исключает типовые каталоги и файлы. Доступ Git настраивается credential manager или отдельным ключом; токены не включаются в URL remote.

Git bundle защищает историю кода, но не заменяет `pg_dump`, backup media и проверку восстановления. Gitea находится на этом NAS, поэтому NAS-копия и mygithub.uz используют один сервер. GitHub даёт внешнюю копию кода; место внешней шифрованной копии рабочих данных предстоит определить перед production согласно требованиям M1.

При запуске приложения на NAS: отдельный Docker Compose project `ijara360`, именованные сервисы/сеть и выделенные каталоги. Существующие проекты NAS не меняются. Порты приложения выбираются после проверки занятости; `192.168.1.105` — адрес локальной сети, внешний доступ/домен пока не настроены. Секреты и backup jobs добавляются при реализации, без преждевременного запуска пустых сервисов.
