# Отчёт: проектирование M1

Дата: 25 сентября 2026. Результат: подготовлен проект Foundation v0.1; ожидает фиксации владельцем перед реализацией. Основание — раздел 43 исходного задания: «После проектирования дать отчёт и остановиться перед большой реализацией следующего этапа».

## Что подготовлено

- Архитектура модульного backend и PostgreSQL, границы M1–M7.
- Две роли OWNER/ADMIN, разрешения в пределах дома, защита последнего владельца.
- Модель пользователей, членств, дома, комнат, мест, сессий, приглашений и аудита.
- SQL-проект из 11 таблиц с FK, уникальностью и проверками значений; отдельно перечислены обязательные транзакционные ограничения.
- Контракт API с валидацией, ошибками, версиями, идемпотентностью и mobile/browser auth.
- Сценарии мобильной настройки, текстовые wireframes и состояния ошибок.
- Матрица тестирования, критерии приёмки, порядок реализации и шаблон change request.

## Ключевые решения

1. Место — основная единица аренды; UUID сохраняется вместе с историей.
2. Занятость будет вычисляться из Occupancy в M2. Вручную выставить OCCUPIED нельзя.
3. Вместимость защищается транзакцией и блокировками, дубликаты — ограничениями БД.
4. Роли проверяются backend в контексте дома; клиент не определяет права.
5. Бизнес-изменение и audit фиксируются вместе; архив сохраняет историю.
6. В M1 нет фиктивных жильцов, платежей, долгов или сведений с камер.

## Допущения для фиксации

Первый запуск: один дом, русский язык, UZS, Asia/Tashkent; логин/пароль без SMS. OWNER меняет структуру и цены, ADMIN — состояния свободных мест. Резерв ручной, без срока и закреплённого жильца. Нет override вместимости. Начальные комнаты/места вводит владелец, примеры задания не импортируются как факты.

Эти решения обратимы на стадии проекта. Framework и мобильная технология выбираются при реализации. Последующим уточнением владельца сервер определён: NAS UGREEN DXP4800 Plus, 192.168.1.105; код и документация должны храниться также в GitHub и mygithub.uz (см. [инфраструктуру](INFRASTRUCTURE.md)). Аппаратная часть камер сейчас не требуется. Финансовые правила неполного месяца и депозитов фиксируются перед M3.

## Проверка и ограничения

Проверены структура документов, внутренние ссылки и согласованность описанных сущностей, прав и этапов. Статическая проверка 7 Markdown-документов подтвердила существование локальных ссылок и корректность JSON-примеров; все REFERENCES в SQL ссылаются на объявленные таблицы, имена 11 таблиц уникальны. Это не проверка синтаксиса или исполнения PostgreSQL. SQL содержит проект декларативной схемы; обязательные процедуры, привилегии, audit guard и серверные правила перечислены явно.

PostgreSQL-схема не развёрнута, runtime/API/UI не созданы. SQL не исполнялся в PostgreSQL; unit/integration/API/UI tests и backup restore не выполнялись. Матрица приёмки — план будущих тестов, не сообщение об их прохождении.

Для обоснования PostgreSQL constraints/locking и auth-практик просмотрена официальная документация PostgreSQL и OWASP; ссылки приведены в [архитектуре](M1-FOUNDATION.md).
