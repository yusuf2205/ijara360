# M7 — Геолокация жильцов + Яндекс Карты (план)

ТЗ владельца от 15 октября 2026. Решения владельца:

| Вопрос | Решение |
|---|---|
| Хранение истории перемещений | 30 дней (`LOCATION_HISTORY_RETENTION_DAYS=30`), затем автоматическое удаление |
| Работа в фоне | Да, **без постоянного уведомления** |
| Карта | Яндекс Карты. Начать с бесплатного ключа (см. ограничение ниже) |

## Ограничения, о которых владелец предупреждён

**Лицензия Яндекса.** Бесплатные условия JavaScript API ([п. 5.1.3](https://yandex.ru/legal/maps_api/)) запрещают «системы мониторинга транспортных средств, людей» с отображением в реальном времени. Пункт 4.1.1 запрещает использовать бесплатный API в закрытых сервисах. Коммерческая лицензия JS API стоит 195 000 ₽ в год ([тарифы](https://yandex.ru/maps-api/tariffs)). Поэтому:
- Карта сделана через адаптер. Ключ хранится только в секретах сервера (`YANDEX_MAPS_API_KEY`) и не попадает в код.
- Ключ записывает владелец на NAS: `sudo sh scripts/configure-map-key.sh` из выпущенного релиза (скрытый ввод, проверка вида ключа, копия `production.env.before-map-*`; «удалить» убирает ключ), затем повторный выпуск. В кабинете Яндекса у ключа JavaScript API включено ограничение HTTP Referer: `mynas.tail4bf75c.ts.net`, `192.168.1.105`.
- Тесты используют подменный модуль карты и не обращаются к Яндексу.
- На production карта включается только после коммерческого ключа. До этого раздел «Карта» показывает список, счётчики и статусы, а на месте карты — «Карта не подключена». Данные собираются и хранятся независимо от карты.

**Фон без уведомления.** Android разрешает частые фоновые обновления только приложениям с постоянным уведомлением (foreground service). Без уведомления фоновая отправка идёт через WorkManager: система запускает её **не чаще раза в 15 минут**, а в режиме экономии (Doze) реже. Обойти это нельзя (ТЗ §6). Последствия:
- Пока приложение открыто, точки идут часто (раз в 30 с при движении).
- В фоне точка уходит раз в 15–30 минут. Поэтому статус по умолчанию считается так: LIVE ≤ 3 мин, STALE ≤ 35 мин, дальше OFFLINE (`LOCATION_LIVE_SECONDS=180`, `LOCATION_STALE_SECONDS=2100`). Иначе фоновые жильцы всё время мигали бы в OFFLINE.
- Разрешение «Разрешить всегда» жилец даёт сам в системном окне. Android периодически напоминает ему, что приложение использует местоположение в фоне. Это поведение системы, оно не скрывается.

**iOS** не проверяется: нет Mac и аккаунта Apple Developer. В отчёте будет «NOT TESTED».

## Согласие и прозрачность

- Отдельный экран «Геолокация» в приложении жильца: что передаётся, кому видно, сколько хранится. Кнопка «Включить» запускает системный запрос разрешения.
- Включение и выключение записываются (`consented_at` / `withdrawn_at`). Выключение в приложении сразу останавливает отправку, сотрудники видят LOCATION_DISABLED (причина: жилец отключил).
- В приложении всегда показан реальный статус ОС: разрешение, службы геолокации, работа в фоне. Фальшивых переключателей нет.
- После выселения (нет активного проживания) сервер отклоняет точки, приложение останавливает сбор, текущая позиция удаляется. История удаляется по сроку хранения.

## Данные

- `resident_location_current`: последняя принятая позиция и телеметрия (разрешение, службы, фон), статус, `last_seen_at`.
- `resident_location_points`: история. Уникальность `(session_id, sequence)` — дедупликация. Индексы `(resident_id, recorded_at)` и `(recorded_at)`.
- `resident_location_settings`: согласие и основное устройство (одна сессия жильца — основной телефон; точки с других устройств не смешиваются).
- Устройство = сессия жильца (M5). Выход или отзыв сессии мгновенно прекращает приём её точек.
- PostGIS не нужен: обычных `double precision` и индексов достаточно для десятков жильцов.

## API

Жилец (сессия жильца, `residentId` никогда не принимается от клиента):
- `GET /api/tenant/location`: свой статус, согласие, основное устройство, последняя отправка.
- `POST /api/tenant/location/consent`: включить или выключить передачу, сделать это устройство основным.
- `POST /api/tenant/location`: точки, до 100 за раз (буфер после офлайна), плюс телеметрия. Отвечает быстро: без расчётов, внешних вызовов и Telegram.

Сотрудники (`VIEW_LOCATION`, история — `VIEW_LOCATION_HISTORY`; владелец — всегда):
- `GET /api/locations`: все жильцы дома со статусами и последней позицией.
- `GET /api/residents/:id/location`: одна карточка (аудит `RESIDENT_LOCATION_VIEWED`).
- `GET /api/residents/:id/location/history?from&to`: история за период до 31 дня (аудит `RESIDENT_LOCATION_HISTORY_VIEWED`, без координат в аудите).
- `GET /api/map/config`: ключ карты для авторизованных сотрудников (или «не настроено»).

## Статусы и фоновые процессы

- LIVE / STALE / OFFLINE по возрасту последней валидной точки. LOCATION_DISABLED — если приложение сообщило, что разрешение или службы выключены, или жилец отключил передачу. Если после этого устройство замолчало дольше порога, статус становится OFFLINE.
- Процесс статусов (каждые 30 с) пересчитывает статусы в базе и публикует `resident.location.status_changed` после фиксации.
- Процесс хранения (раз в час) удаляет точки старше 30 дней и снимает текущие позиции выселенных. Аудит фиксирует только количество.
- Оба процесса отмечают время работы. `/api/health` их отдаёт, сторож M6 проверяет: «Геолокация: приём», «Геолокация: статусы», «Геолокация: очистка», «Карта».

## Реальное время

Существующий канал M5, тема `location`, право `VIEW_LOCATION`: события `resident.location.updated` и `resident.location.status_changed` после фиксации транзакции. Жилец получает события только о себе.

## Конфиденциальность

Координаты не пишутся в журналы, адреса, аудит и Telegram. Тесты проверяют журналы API на отсутствие координат.

## Этапы

1. База и права: миграция, `VIEW_LOCATION`, `VIEW_LOCATION_HISTORY`.
2. API жильца: приём, проверка, дедупликация, буфер, основное устройство, выселение.
3. API сотрудников, статусы, реальное время, хранение, аудит, сторож.
4. Веб: раздел «Карта» (счётчики, фильтры, поиск, список, карта, карточка), геолокация в карточке жильца, история, сводка на главной, права в настройках.
5. Flutter: экран жильца «Геолокация», сбор (открыто: поток; фон: WorkManager), буфер офлайн, раздел «Карта» для сотрудников: список со статусами, у жильца с точкой кнопка «Открыть в Яндекс Навигаторе» (если его нет, Яндекс Карты, затем браузер). В ссылку уходят только координаты, без имени; координаты берутся из `GET /api/residents/:id/location`, поэтому просмотр записывается в журнал так же, как на сайте. Ключ API для этого не нужен.
6. Тесты: сервер, интерфейс (с подменной картой), Flutter. Затем проверка на телефоне владельца и замер батареи.
7. Выпуск: backup, миграция на копии, deploy, проверка на production, отчёт.
