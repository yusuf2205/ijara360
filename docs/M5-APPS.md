# M5 — Apps & Accounts (план)

Решения владельца от 7 октября 2026:

| Вопрос | Решение |
|---|---|
| Вход жильца | Одноразовая ссылка-приглашение через @ijara360bot, жилец сам задаёт пароль |
| Доступ из интернета | Открыть всё: анкета, приложение жильца и кабинет сотрудников |
| Платформы | Android (APK) и веб сейчас; Windows после установки Visual Studio; iOS после появления Mac и Apple Developer |
| Уведомления | Лента в приложении + дублирование в Telegram-боте |

Так как кабинет с паспортами становится доступен из интернета, вход сотрудника с нового устройства из интернета подтверждается в Telegram. Из LAN и Tailscale вход работает как сейчас.

## Этапы

Каждый этап: код → backend-тесты → UI-тесты → ревью. Выпуск на production один, в конце, после полного регресса M1–M4.

1. **Права и сессии.** Отдельные права для функций M1–M3: `ROOMS_MANAGE`, `RESIDENTS_MANAGE`, `FINANCE_VIEW`, `FINANCE_MANAGE`, `STAFF_MANAGE`. Миграция выдаёт существующим ADMIN права, равные их сегодняшним возможностям, поэтому поведение M1–M3 не меняется. Устройства и сессии: «запомнить устройство» (30 дней), список устройств, завершение сессии, Bearer-токены для приложения.
2. **Аккаунты жильцов.** `TenantAccount`, приглашение через бота (ссылка 48 часов, одноразовая), задание пароля, вход по телефону и паролю, устройства жильца. Для жильцов без Telegram — ссылка-приглашение, которую сотрудник передаёт сам.
3. **API жильца.** Профиль, комната и место, начисления, оплаты, остаток, аванс, финансовый допуск, только чтение и только своё.
4. **Обращения.** Жалобы, предложения, поломки. Автора видит только SUPER_ADMIN (OWNER), остальные сотрудники получают обезличенные данные на уровне API. Права `TICKETS_VIEW`, `TICKETS_MANAGE`.
5. **Уведомления и лента.** Таблица уведомлений (жильцу и сотруднику), прочитано / не прочитано, доставка в Telegram через очередь с повторными попытками. События: оплата зачтена, начисление создано, ответ на обращение, приглашение.
6. **Realtime-основа (для M6).** Общий канал событий вместо отдельного канала заявок: темы, фильтр по правам и по жильцу, переподключение с повторной загрузкой состояния.
7. **Публичный доступ к кабинету.** Funnel :8443 обслуживает весь сайт; подтверждение входа с нового устройства через Telegram для сотрудников; привязка Telegram в настройках.
8. **Flutter-приложение `apps/mobile`.** Одно приложение: после входа открывается режим жильца или сотрудника. Жилец: главная, оплаты, обращения, уведомления, профиль и устройства. Сотрудник: заявки, жильцы, финансы, обращения — с учётом прав. Мобильный дизайн из прототипа. Сборка Android APK и веб-версии (`/app`).
   Планка качества (решение владельца): подача заявки в приложении должна выглядеть лучше эталонов «Face ID / E-KYC». Это список шагов с отметками и кольцом прогресса, своя камера с рамкой паспорта, подсказками о бликах и размытости и пересъёмкой, овал для фото лица, экран успеха и одна крупная кнопка на экран. Распознавание текста и сверку лица в этом этапе не делаем, только визуальные подсказки.
9. **Проверка и выпуск.** Регресс M1–M4, тесты M5, backup, миграции на копии, deploy, проверка на production, отчёт PASS.

## Не входит в M5

Карты и геолокация (M7), камеры и доступ в здание (M8), AI (M9), гости, push через Firebase, публикация в Google Play и App Store.
