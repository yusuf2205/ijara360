## Данные и правила

- `Resident`: дом, ФИО, нормализованный E.164 телефон, optional note/photoUrl, timestamps. Уникальность телефона внутри дома. Текущего места в Resident нет. Фото — необязательное поле; загрузчик фотографий не входит в M2, внешние URL не принимаются.
- `Occupancy`: дом, жилец, комната, место, даты, цена, день оплаты, депозит, ACTIVE/CLOSED, автор и timestamps.
- Миграция `202609250002_residents_occupancy` добавляет таблицы, составные FK, два частичных уникальных индекса ACTIVE (bed/resident), CHECK-ограничения и защиту истории. Первая миграция сохранена побайтно.
- Составные FK не допускают смешивания домов, комнаты/места и сотрудника даже при прямой записи в БД.
- Комната и место вычисляют занятость по ACTIVE Occupancy. Финансовые начисления и платежи отсутствуют.
- OWNER и ADMIN могут создавать/редактировать жильцов, заселять, переселять, выселять. Изменять комнаты и сотрудников по-прежнему может только OWNER.
- Все записи сериализуются блокировкой строки дома; после блокировки повторно проверяется активный доступ. История и аудит записываются в той же транзакции.
- Переселение закрывает исходное проживание и создаёт новое, сохраняя цену/день оплаты/депозит. Старые ссылки на место не изменяются. Закрытую историю нельзя изменить/удалить; у runtime-роли отсутствует DELETE для жильцов и проживаний.
- Телефон повторного жильца не создаёт дубль: UI предлагает существующую карточку, API отвечает понятным конфликтом.
- Даты — календарные YYYY-MM-DD, без времени. Сегодня определяется в Asia/Tashkent. Будущие даты и даты до заселения отклоняются. Новое заселение не может быть раньше завершения прежнего проживания жильца или освобождения места. Переселение/выселение в день заселения допускается.
- Суммы принимаются строкой, сохраняются как Decimal(14,2), неотрицательные. День оплаты 1–31 хранится как условие; правила начисления за короткий месяц относятся к M3.
- Audit: RESIDENT_CREATED, RESIDENT_UPDATED, OCCUPANCY_CHECKED_IN, OCCUPANCY_TRANSFERRED, OCCUPANCY_CHECKED_OUT. Содержит идентификаторы жильца/проживаний/старых и новых мест, автора и время; телефон и заметки в metadata не копируются.

## API

Сохраняется префикс `/api`, cookie auth и существующая защита Origin/X-Ijara-Request.

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/residents?q=&filter=all\|active\|closed | Жильцы, поиск, фильтр |
| GET | /api/residents/:id | Карточка и все проживания |
| POST | /api/residents | Создать карточку без заселения |
| PATCH | /api/residents/:id | Обновить ФИО/телефон/заметку |
| POST | /api/occupancies/check-in | Заселить существующего или атомарно создать и заселить нового |
| POST | /api/occupancies/:id/transfer | Переселить активное проживание |
| POST | /api/occupancies/:id/check-out | Завершить активное проживание |

Check-in: ровно одно из `residentId` или `resident: {fullName,phone,note?}`, плюс `bedId,moveInDate,monthlyPrice,paymentDay,depositAmount`. Room/property определяются сервером. Transfer: `bedId,transferDate`. Check-out: `moveOutDate`. PATCH resident принимает fullName и phone, optional note/photoUrl. Чужие ID возвращают 404. Конфликты состояния — 409 с русским сообщением; ошибки ввода — 422.

## UI

Навигация: Главная, Комнаты, Жильцы, История, Настройки. Большая кнопка «Заселить». Четыре шага: жилец → свободное место → условия → подтверждение. На свободном месте есть действие заселения; занятое показывает жильца, телефон, дату, цену и ссылку на карточку.

`/residents`: поиск имени/телефона, Все/Сейчас живут/Выселенные. Новая карточка без проживания имеет статус «Не заселён». `/residents/:id`: данные, заметка, условия, действия и полная история. «Заселить снова» использует прежнюю карточку.

## Backup

`sh scripts/backup-nas.sh` на NAS создаёт `pg_dump -Fc` в `/volume1/docker/ijara360/backups/ijara360-<UTC timestamp>-<pid>.dump`, SHA-256, приватные права, retention 14 дней. Сначала записывается `.partial`, готовый файл появляется только после успешного дампа.

`sh scripts/verify-backup-nas.sh <полный путь dump>` проверяет SHA-256 и восстанавливает дамп в отдельный временный PostgreSQL без сети, опубликованных портов и host data mounts. Контейнер и его временный volume удаляются после проверки. Рабочая БД не изменяется.

Предмиграционная копия рабочей БД создана и проверена восстановлением. Включение ежедневного расписания и внешняя копия резервных данных — отдельные operational items; автоматическое расписание пока не включено.
