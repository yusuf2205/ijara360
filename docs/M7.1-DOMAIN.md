# M7.1 — свой домен ijara360.uz

## Что получается

| Адрес | Для кого | Защита |
|---|---|---|
| `https://ijara360.uz` | заявки (`/apply`), приглашения (`/invite`), приложение жильца (`/app`, APK), API для телефонов | правила публичного входа: вход сотрудника с нового устройства подтверждается в Telegram |
| `https://admin.ijara360.uz` | кабинет сотрудников | Cloudflare Access (вход только с разрешённых почт по коду) + те же правила публичного входа |
| `https://mynas.tail4bf75c.ts.net:8446` | кабинет через Tailscale | как раньше |
| `https://192.168.1.105:8446` | кабинет в домашней сети | как раньше |

Страницы кабинета на `ijara360.uz` (`/`, `/login`, `/residents`, `/map` …) переадресуются на `admin.ijara360.uz`. Корень `ijara360.uz` открывает форму заявки.

## Как устроено

- Cloudflare Tunnel: контейнер `tunnel` (`cloudflare/cloudflared:2026.9.3`) сам подключается к Cloudflare. Порты в роутере не открываются, белый IP не нужен.
- Оба адреса в настройках туннеля ведут на `http://gateway:8082`. У этого входа нет порта на NAS: до него доходит только контейнер туннеля. Он работает по правилам публичного входа (`X-Ijara-Channel: public`): `/api/health` и вебхук Telegram закрыты (404).
- HTTPS-сертификат для `ijara360.uz` и `admin.ijara360.uz` выдаёт Cloudflare.
- **Cloudflare расшифровывает трафик на своей стороне** (видит данные в пути, в том числе загрузку документов). Хранятся данные только на NAS. Владелец согласился на это 2026-10-15. Через Tailscale шифрование по-прежнему идёт до самого NAS.
- Cloudflare Access защищает веб-кабинет на `admin.ijara360.uz`. API на `ijara360.uz/api` открыт для приложений на телефонах и защищён сервером (пароль, подтверждение нового устройства в Telegram, права сотрудника).
- Карта Яндекса: в ограничении ключа HTTP Referer добавить `ijara360.uz` и `*.ijara360.uz`.

## Шаги владельца в Cloudflare (dash.cloudflare.com)

1. **Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared**, имя `ijara360`. На шаге установки скопируйте команду с длинным токеном `eyJ…` (её не нужно запускать, токен вводится в скрипт).
2. **Public hostnames** туннеля, три записи, у каждой Service `HTTP` и URL `gateway:8082`:
   - `ijara360.uz`
   - `admin.ijara360.uz`
   - `www.ijara360.uz`
3. **Zero Trust → Access → Applications → Add an application → Self-hosted**:
   - Application domain: `admin.ijara360.uz`;
   - Policy: Action `Allow`, Include `Emails` — почты сотрудников, которым нужен кабинет;
   - Login method: `One-time PIN` (код на почту).
4. **Speed → Optimization**: выключить Rocket Loader (меняет скрипты страниц).

## Подключение на NAS

1. Выпустить версию с поддержкой домена (`Deploy-Nas.ps1`).
2. `sudo sh scripts/configure-domain.sh` из выпущенного релиза:
   - токен вводится скрыто (можно вставить всю команду установки: берётся последнее слово);
   - временный туннель проверяет, что `https://ijara360.uz/apply` открывается, `admin.ijara360.uz` закрыт Access, `/api/health` закрыт;
   - только после этого сохраняет `CLOUDFLARE_TUNNEL_TOKEN`, `PUBLIC_DOMAIN`, `WATCH_DOMAIN`, добавляет оба адреса в `ADDITIONAL_APP_ORIGINS`, ставит `PUBLIC_APP_ORIGIN=https://ijara360.uz` (ссылки в приглашениях и Telegram); копия `production.env.before-domain-*`;
   - «удалить» отключает домен и возвращает ссылки на адрес Tailscale.
3. Ещё раз `Deploy-Nas.ps1`: туннель запускается как сервис (профиль `tunnel`), выпуск проверяет вход изнутри (`scripts/check-domain.cjs`) и снаружи (`https://ijara360.uz/apply`).

Панель «Сервер» показывает «Вход через домен»: проверка раз в минуту через интернет и Cloudflare.

## Потом

Приложение на телефонах обращается к `https://mynas.tail4bf75c.ts.net:8443`. Переключить его на `https://ijara360.uz` — отдельным выпуском приложения, когда домен проработает несколько дней. Старый адрес остаётся рабочим, поэтому уже установленные приложения не ломаются.

## Без Cloudflare Access (решение владельца, 2026-10-17)

Владелец убрал Cloudflare Access с `admin.ijara360.uz`: страница входа в кабинет открыта из интернета. Защита — та же, что у адреса Tailscale :8443 (публичный вход): пароль, ограничение попыток входа и подтверждение нового устройства в Telegram. Пока сотрудник не привязал Telegram, вход через домен с нового устройства отклоняется; привязка делается после входа через Tailscale или домашнюю сеть. `configure-domain.sh` больше не требует Access, только сообщает, включён ли он. Вернуть: Zero Trust → Access controls → Applications → Self-hosted для `admin.ijara360.uz`.
