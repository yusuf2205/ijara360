# MVP: первый раунд разработки

Дата: 25 сентября 2026. Новое задание владельца заменяет прежнее ограничение «только проектирование M1». Разработка ведётся по порядку: foundation → жители/проживание → финансы → dashboard → приёмка MVP.

## Реализовано

NestJS 11.2.6, Prisma 6.19.3, PostgreSQL 17, Next.js 16.3.6 и TypeScript. Один responsive web-клиент. Шрифты и иконки поставляются вместе с приложением, внешние CDN для UI не требуются. Lockfile закрепляет зависимости. Для deepmerge-ts применён override 8.0.0, устраняющий предупреждение npm audit в цепочке Prisma config; генерация клиента, миграции и сборка проверены с этим override.

Сущности: Property, User, Session, Room, Bed, AuditLog, RateBucket. Семь прикладных таблиц плюс служебная таблица Prisma migrations. Один сотрудник принадлежит одному дому; телефон сотрудника уникален. Роли только OWNER/ADMIN. Контекст дома определяется пользователем на сервере, в DTO не передаётся.

Комнаты создаются с указанным количеством мест. Можно изменить номер/вместимость комнаты, добавить недостающие места, создать/отключить ADMIN и сменить собственный пароль. UI: первоначальная настройка, вход, обзор, комнаты, комната/места, история, настройки дома и сотрудников. Архива/удаления пока нет. Все изменения записываются в аудит.

Первый владелец создаётся через одноразовую настройку по секретному ключу. Создание дома, OWNER, комнат и мест — одна транзакция с advisory lock. Повторная настройка отклоняется. Demo seed запускается только явно, в отдельной БД с суффиксом `_demo`; создаёт 7 комнат и 59 мест. Жильцы в seed появятся вместе с модулем Occupancy.

## Защита данных

- Нормализация телефона E.164, уникальность в БД, строгая DTO-валидация без лишних полей.
- Пароли: scrypt с отдельной солью (N=32768, r=8, p=1). Сессии: случайный 256-bit token, только SHA-256 digest в PostgreSQL, срок 24 часа.
- Browser cookie HttpOnly/SameSite=Strict/Secure в production. Все изменения требуют точный Origin и нестандартный заголовок X-Ijara-Request: 1; CORS не открыт. HTTPS обязателен в production.
- Ограничение попыток входа сохраняется в БД; отзыв ADMIN/смена пароля отзывают сессии. Роль не выбирается при входе. OWNER нельзя отключить через API.
- Вместимость проверяется сервером в транзакции и триггерами PostgreSQL. Конкурирующие записи в пределах дома сериализуются. Версия комнаты защищает редактирование от затирания.
- Runtime DB role `ijara_app` отделена от владельца миграций. Нет DELETE бизнес-таблиц; audit разрешает только SELECT/INSERT и дополнительно защищён триггером от UPDATE/DELETE.
- Секреты, дампы, рабочие данные и ключи исключены из Git. Production и test/demo используют разные контейнеры/БД/настройки.

## Контракт текущего API

Префикс `/api`. Cookie auth. POST/PATCH требуют `Origin` и `X-Ijara-Request: 1`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | Проверка доступности PostgreSQL |
| GET | /auth/setup-status | Выполнена ли первоначальная настройка |
| POST | /auth/setup | Создать первый дом/OWNER/комнаты по X-Setup-Token |
| POST | /auth/login | Телефон + пароль, cookie session |
| GET | /auth/me | Текущий пользователь и серверная роль |
| POST | /auth/logout | Завершить сессию |
| POST | /auth/password | Смена пароля, отзыв всех сессий |
| GET/PATCH | /property | Данные своего дома; изменение только OWNER |
| GET | /dashboard | Количество комнат/мест и вместимость foundation |
| GET/POST | /rooms | Список / создание комнаты |
| GET/PATCH | /rooms/:id | Детали / изменение номера и вместимости с version |
| POST | /rooms/:id/beds | Добавление места |
| GET | /audit | Последние 100 событий; ADMIN видит только операции дома |
| GET/POST | /users | OWNER: список / создание ADMIN |
| PATCH | /users/:id | OWNER: включить/отключить ADMIN |

POST /rooms: `{ "number": "8", "capacity": 9, "bedCount": 8 }`. PATCH комнаты: `{ "number": "8", "capacity": 9, "version": 1 }`. POST места: `{ "number": "9" }`. Создание ADMIN: fullName, phone, password; роль устанавливает сервер. Ошибки: 401 вход, 403 доступ/Origin, 404 чужой/отсутствующий объект, 409 конфликт, 422 DTO, 429 rate limit.

Bed не хранит изменяемый флаг занятости. В первом раунде все созданные места AVAILABLE: данных о проживании ещё нет. В следующем раунде OCCUPIED будет вычисляться из активной Occupancy. UI прямо обозначает эту границу. Финансовые показатели не подменяются нулями.

## Проверки раунда

- Backend: 19 тестов Node test runner/Supertest на реальном PostgreSQL — пройдены, включая гонки через API и прямые DB writes, bootstrap, auth/RBAC, отзыв доступа, аудит/rollback, ошибки JSON и точность сводки.
- Frontend: 7 Playwright-сценариев — пройдены. Настройка и вход, dashboard/room detail, создание комнаты/места с reload, ошибка дубликата с сохранением ввода, поиск/история при 320 px, управление ADMIN, фильтр свободной вместимости и выход с телефона. Проверены ширины 320, 390 и 1440 px.
- Сборка API и production-сборка Next.js выполнены. TypeScript проходит; npm audit после override — 0 уязвимостей.
- Миграция `202609250001_foundation` применена в test, demo и production. Demo seed создаёт 7 комнат / 59 мест, в production не запускался.

После перезапуска test PostgreSQL и API сохранились 8 комнат, 59 мест и действующая сессия; проверено равенство всех данных комнат до/после. HTTPS health и экран первоначальной настройки production отвечают 200; цепочка сертификата проверена с публичным CA, экран не выдаёт ошибок JavaScript. Production остаётся без demo-данных и ожидает настройки владельцем. Проверки заселения/переселения/выселения, платежей и долгов ещё не существуют: соответствующие модули будут реализованы в следующих раундах.

## Что осталось до MVP

Resident, Occupancy с двумя уникальными ограничениями активного проживания, заселение/переселение/выселение, Charge, Payment/распределение, частичные оплаты/долги и финансовый dashboard. До использования реальных финансов нужны тесты этих сценариев и ежедневное резервное копирование с проверкой восстановления. Импорт, камеры и AI отложены.

Следующий шаг: Resident + Occupancy и цепочка «заселить → переселить → выселить», сохраняя историю и защищая место от двойного заселения.
